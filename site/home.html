AG Grid requests in.
Safe queries out.

Craticula turns AG Grid server-side requests into native, injection-safe SQL, MongoDB and OpenSearch queries. It compiles the query and never runs it; you run it with your own driver.

AG Grid request
{
  "startRow": 0, "endRow": 50,
  "filterModel": {
    "customer": { "type": "contains", "filter": "acme" },
    "amount": { "type": "greaterThan", "filter": 100 }
  },
  "sortModel": [ { "colId": "amount", "sort": "desc" } ]
}
PostgreSQL, compiled
SELECT * FROM "orders"
WHERE ("customer" ILIKE '%' || $1 || '%' ESCAPE '\'
   AND "amount" > $2::numeric)
ORDER BY "amount" DESC NULLS FIRST, "id" ASC NULLS LAST
LIMIT $3 OFFSET $4

-- parameters: 'acme', '100', 50, 0

One request, your database

The same request, in each database's own language

Each compiler follows the same normative rules, so the statements for two databases agree on which rows they return.

SQL

Parameterized statements for PostgreSQL and SQL Server, with values carried as parameters and never part of the text.

MongoDB

Native filters and aggregation pipelines from the same request, behind the same schema allowlist.

OpenSearch

The OpenSearch and Elasticsearch query DSL, compiled and never executed by the library.

Compile only

No connection, no driver, no side effects. You get a statement and its parameters and run them where you choose.

Allowlisted by schema

A request for a column the schema does not list is refused before any compiler sees it.

Spec first

A language-neutral spec is the source of truth, and every implementation conforms to it.

From grid request to query in four steps

01

Declare a schema

List the columns a grid may touch. Everything else is refused.

02

Parse the request

AG Grid's JSON becomes the canonical intermediate representation.

03

Compile it

Pick the compiler for your database and get a statement plus parameters.

04

Run it your way

Use your own driver, or an adapter for Dapper, Entity Framework Core, MongoDB or OpenSearch.
