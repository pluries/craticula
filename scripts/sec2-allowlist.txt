# SEC-2 lint allowlist (scripts/lint-sec2.py): the reviewed trust boundaries of the query-text builders.
#
# Two kinds of entry, one per line ('#' starts a comment):
#
#   trust path::Type.Member | position | expression | reason (requirement id)
#     The finding the lint printed, accepted as it stands: nothing inside the expression is traced further. The key
#     is the file, the enclosing member, the POSITION (the `[key: ... | position]` the finding prints: an interpolation
#     hole, a `+` operand, the value of local `x`, argument `p` of `M`, a return value...) and the exact expression
#     (whitespace collapsed). The same text anywhere else in the member, or in another kind of position, is checked
#     again. An entry may not trust a parameter of an ordinary method as it is passed in (`p`, `p.X`, `p[i]`): that
#     would vouch for every call site, present and future. Trust the function that validates the value instead (its
#     return), or the argument at the call site.
#
#   not-query-text path::Type.Member | reason
#     The member's result is never query text. Its own string constructions are not checked; in exchange, a call to
#     it that reaches query text is a finding. For values that are bound or only ever echoed in exception messages.
#
# Add an entry only for a value that is NOT a user value: a quoting, placeholder or escaping primitive's own input, a
# schema-declared identifier, or text that never reaches a query. A user value in query text is a SEC-2 defect to fix,
# never an entry here. An entry that matches nothing in the run fails it (exit 1), and so does an entry whose file
# does not exist or lies outside the scanned files, so this file cannot rot.
